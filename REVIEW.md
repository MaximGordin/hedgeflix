# Project Review — 2026-03-21

## Общая оценка проекта

Hedgeflix стоит на крепком фундаменте — современный стек (NestJS 11, Prisma 7, Next.js 16, Tailwind v4), чистые конвенции кода, продуманная схема БД и амбициозный дизайн на 10+ типов страниц с 46 переиспользуемыми компонентами. Проект на ранней стадии: бэкенд имеет один эндпоинт (GET /movies/:id), фронтенд — только хедер + переключатель темы. Главный риск — разрыв между объёмом дизайна и текущей реализацией, но архитектура готова к масштабированию.

| Область | Статус | Комментарий |
|---------|--------|-------------|
| Архитектура | :green_circle: | Чистые модули NestJS, правильная структура FSD, хорошее разделение |
| Качество кода | :green_circle: | Единый стиль, strict TS, линтинг/форматирование, документированные тесты |
| Покрытие дизайна | :red_circle: | ~5% дизайна реализовано (хедер + тема). 10+ страниц не построены |
| Документация | :green_circle: | README подробный и актуальный. CLAUDE.md поддерживается |
| Тестирование | :yellow_circle: | Хорошие паттерны, но тесты только для 1 сервиса + 1 контроллера |
| Безопасность | :yellow_circle: | Нет модуля авторизации, нет ValidationPipe, нет настройки CORS |
| CI/CD | :yellow_circle: | Lint + format + тесты, но нет шага сборки, нет e2e, нет деплоя |

## :red_circle: Критично — нужно исправить

### [backend/src/main.ts:7] Нет настройки CORS

_Проблема:_ NestJS-приложение создаётся без включённого CORS. Когда фронтенд (порт 3000) начнёт вызывать API бэкенда (порт 3001), все запросы будут заблокированы браузером.

_Решение:_
```ts
const app = await NestFactory.create(AppModule);
app.enableCors({ origin: configService.get('CORS_ORIGIN') ?? 'http://localhost:3000' });
```

### [backend/src/main.ts:7] Нет глобального ValidationPipe

_Проблема:_ Без глобального `ValidationPipe` будущие DTO с декораторами class-validator не будут валидироваться. Единственный эндпоинт использует `ParseIntPipe` — это ок, но как только появятся POST/PATCH-эндпоинты, невалидированные данные попадут в сервисный слой.

_Решение:_
```ts
app.useGlobalPipes(new ValidationPipe({ whitelist: true, transform: true }));
```

## :orange_circle: Важно — стоит исправить в ближайшее время

### [backend/eslint.config.mjs:20] sourceType стоит 'commonjs', а проект использует ESM

_Проблема:_ `tsconfig.json` — ES2023 с `nodenext`-модулями, в `package.json` — `"type": "module"`. ESLint с `sourceType: 'commonjs'` — несоответствие. Сейчас не ломает ничего, но может давать странные результаты линтинга для import/export.

_Решение:_ Заменить `sourceType: 'commonjs'` на `sourceType: 'module'`.

### [backend/src/modules/movies/movies.service.ts] Единственный эндпоинт с минимальным select

_Проблема:_ `getMovie()` выбирает только 5 полей (posterPath, originalTitle, originalLanguage, runtime, tmdbId). Страница фильма в дизайне требует переводы, рейтинги, актёров, съёмочную группу, видео, сертификации, жанры, награды, похожие фильмы и рекомендации.

_Решение:_ При построении детальной страницы создать отдельный метод `getMovieDetail()` с полным `include` и вложенными `select`. Текущий лёгкий `getMovie()` оставить для карточек/списков.

### [frontend/src/widgets/ui/Header/Header.tsx:4-5] Нарушение слоёв FSD — виджет импортирует виджеты

_Проблема:_ `Header.tsx` импортирует `LangSwitcher` и `ThemeSwitcher` из `@widgets/ui/`. В FSD виджет не должен импортировать другой виджет — слайсы внутри одного слоя должны быть независимы.

_Решение:_

| Подход | Описание | Плюсы | Минусы |
|--------|----------|-------|--------|
| A: shared/ui | Перенести в `@shared/ui/` | Просто, соблюдает правила FSD | ThemeSwitcher имеет логику состояния |
| B: features | ThemeSwitcher → `@features/theme-switcher/ui/`, LangSwitcher → `@features/lang-switcher/ui/` | Более корректно по FSD — это пользовательские фичи | Больше директорий для маленьких компонентов |

Подход B правильнее. ThemeSwitcher управляет состоянием (Zustand-стор), что делает его фичей, а не чистым UI-элементом.

### [frontend/src/app/layout.tsx:11] Статичный title в корневом layout

_Проблема:_ В корневом layout задан `title: "Hedgeflix | Homepage"`. Этот заголовок будет на всех страницах, если не переопределить. Страница фильма покажет "Hedgeflix | Homepage" во вкладке.

_Решение:_
```ts
// layout.tsx
export const metadata: Metadata = {
  title: { default: 'Hedgeflix', template: '%s | Hedgeflix' },
  description: 'Movie catalog',
};
// movie/page.tsx
export const metadata: Metadata = { title: 'Movie' };
```

### [schema.prisma] Отсутствуют индексы на внешних ключах для фильтрации/сортировки

_Проблема:_ PostgreSQL автоматически индексирует PK и unique-ограничения, но простые FK — нет. Колонки `MovieCast.personId`, `MovieCrew.personId`, `Comment.movieId`, `Comment.userId`, `PersonImage.personId` не проиндексированы. Запросы "все фильмы актёра" или "все комментарии к фильму" будут делать sequential scan при росте данных.

_Решение:_
```prisma
model MovieCast {
  // ...
  @@index([personId])
}
model Comment {
  // ...
  @@index([movieId])
  @@index([userId])
}
```

### [packages/shared/ не существует] Shared-пакет не создан

_Проблема:_ CLAUDE.md и README упоминают `packages/shared/` (`@hedgeflix/shared` — общие типы, DTO, константы), но директория не создана. Без общих типов между фронтендом и бэкендом типы будут расходиться по мере роста API.

_Решение:_ Создать пакет до построения эндпоинта списка фильмов. Как минимум — общие response DTO и enum-типы (источники рейтингов, статусы фильмов и т.д.).

## :yellow_circle: Предложения — стоит улучшить

### [.github/workflows/ci.yml] CI не запускает шаг сборки

_Проблема:_ CI гоняет lint + format:check + тесты, но не запускает `pnpm build` ни для бэкенда, ни для фронтенда. Успешный lint не гарантирует компиляцию — ошибки TypeScript в неиспользуемых путях кода или в конфигурации сборки не обнаружатся.

_Решение:_ Добавить `cd backend && pnpm build` и `cd frontend && pnpm build` после тестов.

### [frontend/src/widgets/ui/ThemeSwitcher/ThemeSwitcher.tsx:21-33] Вспышка неправильной темы при SSR

_Проблема:_ Тема применяется через `useEffect` (только на клиенте). При первой загрузке HTML рендерится без атрибута `data-theme`, затем запускается эффект. Пользователи с тёмной темой увидят вспышку светлой.

_Решение:_ Добавить инлайн-`<script>` в `<head>` layout.tsx, который читает localStorage и ставит `data-theme` до гидратации React:
```tsx
<script dangerouslySetInnerHTML={{ __html: `
  (function() {
    var t = JSON.parse(localStorage.getItem('theme') || '{}');
    var theme = t?.state?.theme || 'system';
    var dark = theme === 'dark' || (theme === 'system' && matchMedia('(prefers-color-scheme:dark)').matches);
    document.documentElement.setAttribute('data-theme', dark ? 'dark' : 'light');
  })()
`}} />
```

### [backend/scripts/seed-movies.ts] Скрипт-монолит на 860 строк

_Проблема:_ Сид-скрипт вырос с множеством обязанностей (CLI-парсинг, API-вызовы, маппинг данных, upsert в БД). `upsertMovieFromDetails` — ~190 строк. Не блокирует, но тяжело поддерживать.

_Решение:_ При следующей модификации — разбить на модули: `cli.ts`, `tmdb-client.ts`, `omdb-client.ts`, `mappers.ts`, `seed.ts`.

### [backend/src/modules/movies/movies.controller.ts] Нет документации типа ответа для Swagger

_Проблема:_ `getMovie()` имеет `@ApiOperation`, но нет `@ApiResponse`-декораторов. Swagger-документация не покажет форму ответа.

_Решение:_ Создать DTO-класс и использовать `@ApiResponse({ type: MovieDto })`.

### [frontend] Нет error.tsx и not-found.tsx

_Проблема:_ Next.js App Router поддерживает встроенную обработку ошибок и 404 через специальные файлы. Без них ошибки показывают дефолтную страницу. В дизайне есть кастомная 404.

_Решение:_ Добавить `app/not-found.tsx` (по дизайну 404-страницы) и `app/error.tsx` для runtime-ошибок.

## Рекомендуемые следующие шаги

По приоритету, учитывая зависимости:

1. **CORS + ValidationPipe** — 5 минут, разблокирует связку фронт-бэк
2. **Исправить нарушения слоёв FSD** — перенести ThemeSwitcher/LangSwitcher в features до того, как другие виджеты повторят неправильный паттерн
3. **Шаблон metadata** — исправить title в layout.tsx до добавления новых страниц
4. **Эндпоинт `GET /movies`** — каталог и главная оба его требуют. Пагинация, сортировка, фильтр по жанру, переводы. Создать response DTO в shared-пакете
5. **Главная страница** — hero + слайдеры фильмов + сетка жанров. Первая реальная пользовательская страница
6. **Каталог** — сетка фильмов с фильтрами и пагинацией. Переиспользует MovieCard с главной
7. **Эндпоинт `GET /movies/:id` (полный)** — обогатить существующий эндпоинт includes для страницы фильма
8. **Страница фильма** — самая большая страница, но большинство дизайн-компонентов дебютируют здесь
9. **Модуль авторизации** — нужен до любых пользовательских фич (комментарии, закладки, оценки)
10. **Шаг сборки в CI** — ловить ошибки компиляции до мержа
